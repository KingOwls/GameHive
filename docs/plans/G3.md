## Contrato

- `GET /functions/v1/reviews?gameId=rawg:ID|manual:UUID`: JWT verificado online, sesión vigente y cuenta activa; devuelve la reseña propia (incluso retirada/oculta), o `null` explícito. No permite consultar otro autor.
- `POST /functions/v1/reviews`: `{action, gameId, version?, input?}`. `action`: `create`, `update`, `withdraw`, `republish`. `input`: `{rating,title,bodyPublic,bodySpoiler,pros?,cons?}`. Pros y contras: hasta cinco entradas de1–200 caracteres cada uno. Update/withdraw/republish requieren versión actual. Las retiradas siguen ocupando identidad y solo republican la misma fila.
- Alta201, resto200; inválidos400, JWT401, estado/rol/sesión/moderación403, propia inexistente en mutación404, duplicado/versión/estado409, fallo saneado503. Ante ACK incierto se comprueba la propia antes de reintentar; el borrador no se sustituye al comprobar.
- Lectura pública: `/rest/v1/reviews` con RLS, filtro de FK, orden `created_at.desc,id.asc`, página de10 y cuenta exacta. Join de perfiles solo `username,avatar_key`. Data API no tiene privilegios de escritura, tampoco `service_role`; funciones privadas no ejecutables por roles API.
- Cuerpo HTTP hasta160000 bytes para admitir Unicode dentro de límites de caracteres. El helper manual mantiene su límite predeterminado20000. Timeout único de10s cubre Auth/cuerpo/pool/query; query cancelable y timeout SQL8s.

## Operación y riesgos

La migración y la función `reviews` se aplican/ejecutan solo en el stack local `gamehive`. No reiniciar el runtime del coordinador sin coordinar. No ejecutar dos suites que construyan/usen `dist` o preview4173 simultáneamente.

`npm run test:reviews -- --e2e` exige una ficha RAWG real completa ya persistida por la verificación de catálogo; crea un registro manual real de Celeste con fuente oficial y cuentas temporales. No inventa una conexión a RAWG si falta esa precondición. `GH_REVIEWS_ISOLATED=1` es la vía CI: crea una fila/documento rotulado como fixture y sustituye solo la respuesta de detalle de catálogo en Playwright; las llamadas de reseñas/Auth/Edge/DB son reales locales. No requiere ni añade secretos RAWG a CI. La fixture RAWG se elimina por ID+marcador, las reseñas por autor de prueba y el juego manual mediante auditoría recuperable incluso sin ACK.
